# Учёт личных расходов студента

Веб-приложение для учёта повседневных трат. Студент добавляет расход (сумма, категория, дата, необязательное описание), а приложение сразу показывает список за выбранный месяц, общий итог и суммы по категориям. Данные сохраняются на сервере в SQLite и остаются после обновления страницы.

Кейс HackAlem AI: «Учёт личных расходов студента» (без ИИ и внешних API).

## Что реализовано

**Обязательный сценарий из ТЗ**
- Форма добавления расхода: сумма (строго > 0), категория (из списка), дата, описание (необязательно).
- Валидация на фронте и бэкенде с понятными сообщениями («Сумма должна быть больше 0», «Выберите категорию» и т. д.). Некорректные данные отклоняются с HTTP 422.
- Список расходов за выбранный месяц с удалением записи (с подтверждением).
- Общий итог за месяц и суммы по категориям (с процентами, полосками и кольцевой диаграммой). Пересчёт при добавлении, удалении и смене месяца. Отдельно показывается контроль «сумма категорий = итог».
- Переключение месяца: стрелки, `<input type="month">`, кнопка «Сегодня».
- Все суммы в одной валюте (₸), без конвертации.
- Сохранение данных: SQLite на бэкенде, после перезагрузки страницы записи остаются.
- Пустое состояние списка и итогов обрабатывается отдельно.

**Дополнительно**
- Редактирование расхода (модальное окно, `PUT /api/products/{id}`).
- Статистика за месяц: средний расход в день, главная категория, самая крупная трата, сравнение с прошлым месяцем (▲/▼ %).
- График динамики по месяцам за год (клик по столбцу открывает месяц).
- Отметка «на кого потратили» (я / друзья / семья …) и итоги по получателям.
- Экспорт расходов за месяц в CSV (`GET /api/products/export.csv`, открывается в Excel).
- Поиск по описанию, фильтр по категории, сортировка по дате/сумме, группировка по дням.
- Месячный бюджет (хранится в `localStorage` браузера) с прогресс-баром и предупреждением о превышении.
- Быстрые суммы (500/1000/1500…), выбор категории плитками с иконками.
- Кнопка «Проверочный пример» — загружает данные из раздела 7 ТЗ (1500 еда, 600 транспорт, 900 еда).
- Кнопка «Очистить всё».
- Адаптивная вёрстка (на телефоне форма открывается кнопкой «+»), тёмная/светлая тема.
- Swagger UI для API: `http://localhost:8001/docs`.
- Автотест проверочного сценария (`backend/test_scenario.py`).

## Как работает решение

1. Пользователь открывает `http://localhost:3000`, выбирает месяц (по умолчанию текущий).
2. Заполняет форму «Добавить расход» → фронт валидирует поля → `POST /api/products` → запись сохраняется в SQLite.
3. Фронт запрашивает `GET /api/products/summary?year=YYYY&month=MM` и получает итог, разбивку по категориям и список трат за месяц.
4. Удаление записи — `DELETE /api/products/{id}`, после чего сводка перезапрашивается и пересчитывается.
5. Все расчёты выполняются на сервере из введённых пользователем данных, заранее подготовленных итогов нет.

## Архитектура

```
client/  (Next.js, :3000)                 backend/  (FastAPI, :8001)
┌──────────────────────────┐   /api/*    ┌──────────────────────────┐
│ app/page.tsx  — экран    │ ──rewrite──▶│ main.py                  │
│ components/expense-form  │             │  POST/GET/PUT/PATCH/DELETE│
│ components/summary       │             │   /api/products          │
│ components/expense-list  │             │  GET /api/products/summary│
│  GET /api/products/export.csv│
│ lib/api.ts — HTTP-клиент │◀────JSON────│  GET /api/categories     │
└──────────────────────────┘             │  POST /api/seed          │
                                         └───────────┬──────────────┘
                                                     ▼ SQLAlchemy
                                               SQLite expenses.db
```

- Фронт ходит на относительный `/api/*`; `next.config.mjs` проксирует эти запросы на бэкенд (адрес задаётся переменной `API_URL`, по умолчанию `http://localhost:8001`). CORS на бэкенде тоже открыт, поэтому можно обращаться и напрямую.
- Архитектура намеренно простая: один файл бэкенда, несколько компонентов на фронте.

## Установка и запуск

Требования: Python 3.9+, Node.js 18+ (и `bun` или `npm`).

```bash
git clone <repo-url> && cd <repo>
./setup.sh      # создаст backend/venv, поставит pip- и npm-зависимости
./start.sh      # запустит бэкенд (:8001) и фронтенд (:3000)
```

Открыть: **http://localhost:3000**. Swagger: http://localhost:8001/docs.

Альтернативы:

```bash
make setup && make dev        # то же самое через Makefile
make backend                  # только бэкенд (с autoreload)
make frontend                 # только фронтенд
make test                     # автотест проверочного сценария
docker compose up --build     # через Docker (фронт :3000, бэк :8001)
```

Ручной запуск по отдельности:

```bash
# backend
cd backend && python3 -m venv venv && ./venv/bin/pip install -r requirements.txt
./venv/bin/uvicorn main:app --reload --port 8001

# frontend (в другом терминале)
cd client && bun install && bun run dev     # или npm install && npm run dev
```

Переменные окружения — см. `.env.example` (`PORT`, `DATABASE_URL`, `API_URL`).

## Как проверить решение (сценарий из ТЗ)

1. Откройте http://localhost:3000, убедитесь, что выбран текущий месяц.
2. Добавьте три расхода за один месяц: **Еда — 1500**, **Транспорт — 600**, **Еда — 900**.
   Ожидаемо: **Всего 3 000 ₸**, Еда — 2 400, Транспорт — 600.
3. Удалите расход на 900 (кнопка «Удалить» в списке).
   Ожидаемо: **Всего 2 100 ₸**, Еда — 1 500, Транспорт — 600.
4. Обновите страницу (F5) — записи и итоги остаются.
5. Попробуйте ввести сумму `-50` или `0` — форма покажет «Сумма должна быть больше 0» и ничего не отправит; API на такой запрос отвечает 422.
6. Переключите месяц стрелками — список и итоги пересчитаются для выбранного месяца (для пустого месяца показывается «Список пуст»).

Тот же сценарий одной кнопкой: «Проверочный пример» (загружает три записи), либо автотестом:

```bash
make test
# или: cd backend && ./venv/bin/python -m pytest -q test_scenario.py
```

## Данные и интеграции

- Внешние наборы данных, API и AI-модели не используются.
- Все расходы вводятся пользователем вручную и хранятся в локальной SQLite (`backend/expenses.db`, в git не попадает).
- Категории фиксированы на бэкенде: Еда, Транспорт, Жилье, Развлечения, Образование, Здоровье, Одежда, Другое.
- Поле «на кого потратили» — свободный текст с подсказками (я, друзья, семья, подарок).
- Месячный бюджет хранится только в браузере (`localStorage`).

## Ограничения

- Нет регистрации и пользователей: одна общая база на сервер (по ТЗ не требуется).
- Хранение на сервере, а не в браузере: для сохранения данных бэкенд должен быть запущен. При недоступном сервере фронт показывает ошибку «Сервер недоступен».
- Нет повторяющихся расходов, напоминаний и уведомлений.
- Одна валюта, без конвертации.
- Развёрнутой (deployed) версии нет — запуск локально по инструкции выше.
