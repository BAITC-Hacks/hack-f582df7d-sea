# Tiyn — учёт личных расходов студента

Tiyn (тиын — сотая часть тенге) — веб-приложение для учёта повседневных трат. Студент добавляет расход с суммой, категорией и датой, а приложение показывает общий итог за месяц, разбивку по категориям, список записей и аналитику. Данные хранятся на сервере в SQLite и остаются после перезагрузки страницы.

Проблема, которую решает проект: без списка и автоматического подсчёта трудно понять, сколько уходит за месяц и какие категории занимают большую часть бюджета. Целевой пользователь — студент, ведущий личный бюджет.

## Что реализовано

**Обязательный сценарий**

- Добавление расхода: сумма (строго больше 0), категория из списка, дата, необязательные описание и «на кого потратили». Неверные данные отклоняются с сообщением на форме и кодом 422 на API.
- Список расходов за выбранный месяц, удаление и редактирование записи.
- Общий итог за месяц и суммы по категориям с процентами. Пересчёт при добавлении, удалении, изменении и смене месяца. Сумма категорий равна итогу.
- Одна валюта (₸), без конвертации.
- Сохранение данных на сервере (SQLite): записи остаются после обновления страницы.

**Дополнительно**

- Обзор: сравнение с прошлым месяцем, средний расход в день, главная категория, крупнейшая трата, график по месяцам за год, последние и крупнейшие записи.
- Расходы: поиск, фильтры по категории и получателю, сортировка, пагинация, дублирование записи, удаление с отменой через уведомление, экспорт месяца в CSV.
- Аналитика: календарь трат за месяц, траты по дням недели, итоги по получателям; за год — категории по месяцам, структура года, таблица категория × месяц.
- Бюджет: общий лимит и лимиты по категориям, использование за месяц с индикацией перерасхода.
- Настройки: тема (светлая, тёмная, системная), загрузка проверочного примера и демо-данных, экспорт всех записей в JSON, удаление всех записей.
- Быстрое добавление из любой страницы кнопкой или клавишей `N`.
- Swagger UI для API: `http://localhost:8001/docs`.

## Как работает решение

1. Пользователь открывает `http://localhost:3000`. По умолчанию выбран текущий месяц; месяц общий для всех страниц и переключается стрелками.
2. Нажимает «Добавить» (или `N`), заполняет форму. Фронтенд проверяет поля, затем отправляет `POST /api/products`. Бэкенд повторно валидирует данные и сохраняет запись в SQLite.
3. Фронтенд запрашивает `GET /api/products/summary?year=YYYY&month=MM`. Бэкенд считает итог, разбивку по категориям и получателям, помесячные суммы за год, средний расход в день, итог прошлого месяца и возвращает список записей.
4. Страницы «Обзор», «Расходы», «Аналитика» и «Бюджет» отображают эти данные. Удаление (`DELETE /api/products/{id}`) и редактирование (`PUT /api/products/{id}`) приводят к повторному запросу сводки и пересчёту.
5. Все расчёты выполняются на сервере из введённых данных, заранее подготовленных итогов нет.

## Технологии

| Слой | Технологии |
|---|---|
| Frontend | Next.js 16 (App Router), React 19, TypeScript, HeroUI v3 (`@heroui/react`, `@heroui/styles`), Tailwind CSS 4, next-themes |
| Backend | Python 3.9+, FastAPI, SQLAlchemy 2, Pydantic 2, Uvicorn |
| База данных | SQLite (файл `backend/expenses.db`) |
| Тесты | pytest, FastAPI TestClient |
| Инфраструктура | shell-скрипты, Makefile, Dockerfile для обоих сервисов, docker-compose |

AI-модели и внешние API не используются.

## Архитектура

```
client/ (Next.js, :3000)                      backend/ (FastAPI, :8001)
┌───────────────────────────────┐            ┌────────────────────────────────┐
│ app/                          │  /api/*    │ main.py                        │
│   page.tsx        обзор       │ ─rewrite─▶ │  products: CRUD, summary, CSV  │
│   expenses/       список      │            │  budgets: GET, PUT             │
│   analytics/      аналитика   │ ◀─ JSON ── │  categories, seed, health      │
│   budget/         бюджет      │            │                                │
│   settings/       настройки   │            │ test_scenario.py               │
│   providers.tsx   состояние   │            └───────────────┬────────────────┘
│ components/       UI          │                            │ SQLAlchemy
│ lib/api.ts        HTTP-клиент │                    SQLite expenses.db
│ lib/hooks.ts      загрузка    │                    (products, budgets)
└───────────────────────────────┘
```

- Фронтенд обращается к относительному пути `/api/*`; `next.config.mjs` проксирует его на бэкенд (адрес задаётся переменной `API_URL`, по умолчанию `http://localhost:8001`). На бэкенде также открыт CORS.
- Общее состояние фронтенда (выбранный месяц, открытые модальные окна, действия создания/изменения/удаления с уведомлениями) находится в `app/providers.tsx`. Данные загружаются хуками из `lib/hooks.ts`.
- Бэкенд — один файл `backend/main.py`: модели SQLAlchemy, схемы Pydantic, эндпоинты. При старте создаются таблицы и при необходимости добавляется колонка `recipient`.

Эндпоинты API:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/categories` | список категорий |
| GET | `/api/products?year&month&category` | список расходов с фильтрами |
| POST | `/api/products` | добавить расход |
| GET / PUT / PATCH / DELETE | `/api/products/{id}` | получить, обновить, удалить расход |
| DELETE | `/api/products` | удалить все расходы |
| GET | `/api/products/summary?year&month` | итоги за месяц или год |
| GET | `/api/products/export.csv?year&month` | экспорт в CSV |
| GET / PUT | `/api/budgets` | лимиты бюджета |
| POST | `/api/seed?demo=true` | проверочный пример, с `demo` — плюс демо-данные |
| GET | `/api/health` | статус и число записей |

## Установка и запуск

Требования: Python 3.9+, Node.js 18+ и `bun` или `npm`.

```bash
git clone <repo-url>
cd <repo>
./setup.sh    # создаёт backend/venv, ставит pip- и npm-зависимости
./start.sh    # запускает бэкенд на :8001 и фронтенд на :3000
```

Открыть `http://localhost:3000`. Swagger: `http://localhost:8001/docs`.

Другие способы:

```bash
make setup && make dev        # то же через Makefile
make backend                  # только бэкенд
make frontend                 # только фронтенд
make build                    # production-сборка фронтенда
docker compose up --build     # оба сервиса в Docker
```

Вручную:

```bash
# бэкенд
cd backend
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
./venv/bin/uvicorn main:app --reload --port 8001

# фронтенд, в другом терминале
cd client
bun install        # или npm install
bun run dev        # или npm run dev
```

Переменные окружения описаны в `.env.example` (`PORT`, `HOST`, `DATABASE_URL`, `API_URL`).

## Как проверить решение

1. Открыть `http://localhost:3000`, убедиться, что выбран текущий месяц.
2. Добавить три расхода за один месяц: Еда — 1500, Транспорт — 600, Еда — 900.
   Ожидается: всего 3 000 ₸, Еда 2 400, Транспорт 600.
3. На странице «Расходы» удалить запись на 900 через меню строки.
   Ожидается: всего 2 100 ₸, Еда 1 500, Транспорт 600.
4. Обновить страницу — записи и итоги остаются.
5. Попробовать сумму `0` или `-50`: форма покажет «Сумма должна быть больше 0», запрос не отправится. Тот же запрос к API вернёт 422.
6. Переключить месяц стрелками — список и итоги пересчитаются, для пустого месяца показывается пустое состояние.

Тот же сценарий одной кнопкой: «Настройки → Проверочный пример». Кнопка «Демо-данные» дополнительно создаёт несколько месяцев трат и лимиты бюджета.

Автотест сценария (добавление, итоги, удаление, пересчёт, отклонение отрицательной суммы, очистка):

```bash
make test
# или: cd backend && ./venv/bin/python -m pytest -q test_scenario.py
```

## Данные и интеграции

- Внешние наборы данных, API и AI-сервисы не используются.
- Все расходы вводятся пользователем и хранятся в локальной SQLite (`backend/expenses.db`, в git не попадает).
- Категории фиксированы на бэкенде: Еда, Транспорт, Жилье, Развлечения, Образование, Здоровье, Одежда, Другое.
- Поле «на кого потратили» — свободный текст.
- Демо-данные генерируются на бэкенде с фиксированным seed.

## Ограничения

- Один пользователь, без регистрации и авторизации; одна общая база на сервер.
- Данные хранятся на сервере, а не в браузере: без запущенного бэкенда фронтенд показывает ошибку.
- Категории нельзя добавлять или переименовывать через интерфейс.
- Одна валюта без конвертации.
- Нет импорта данных, повторяющихся расходов и уведомлений.
- Выбранный месяц не сохраняется между перезагрузками и сбрасывается на текущий.
